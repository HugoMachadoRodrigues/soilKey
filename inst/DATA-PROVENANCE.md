# Data provenance

soilKey ships **no third-party data**. It ships the code that reads it.

That is a deliberate line. Soil databases and the reference works built on them
belong to the institutions that make and curate them, and those institutions
are the ones entitled to distribute them. A user who wants WoSIS data should
obtain it from ISRIC, under whatever terms ISRIC sets, and the same for every
other source. Bundling a convenience copy inside an R package puts the
maintainer in the position of redistributing somebody else's work, removes the
provider's ability to set terms, count usage, or correct the record, and, when
the copy is under a licence such as the GPL, grants rights through soilKey's
MIT licence that the original withholds.

## What the package contains

Everything below was made for soilKey, except the CIE colorimetric tables,
which are a published physical standard.

| Artefact | What it is |
|---|---|
| `data/ossl_demo_sa.rda` | **Synthetic.** Generated by `data-raw/build_ossl_demo.R` with `set.seed(20260430)`. Contains no measured sample. Only the property *ranges* were informed by published OSSL summary statistics. |
| `inst/extdata/*_canonical.rds` (31) | **Constructed by hand.** Idealised profiles written to exercise the keys, one per WRB Reference Soil Group or diagnostic they test. Every identifier follows the `XX-canonical-NN` pattern (e.g. `FR-canonical-01`), and the coordinates are placeholders. |
| `inst/extdata/perfil_exemplo.csv` | A four-horizon worked example, written by hand. |
| `inst/extdata/canonical/wrb2022_diagnostics.csv` | **Compiled for soilKey** by `data-raw/wrb2022_diagnostics_canonical.R`: the names of the 40 diagnostic horizons, 17 properties and 19 materials defined in IUSS Working Group WRB (2022), used to measure coverage. |
| `inst/shiny/.../soilgrids_wrb_demo.tif` | **Synthetic.** Built by `data-raw/make_soilgrids_wrb_demo.R` from sinusoidal fields; not downloaded from SoilGrids. |
| `inst/shiny/.../demo_spectrum.csv` | **Synthetic.** Built by `data-raw/make_demo_spectrum.R` with `set.seed(20260922)`: a smooth continuum with the absorption features of a kaolinitic, hematite-rich Ferralsol. Nothing in it was measured. |
| `inst/shiny/.../demo_profile.jpg` | **Drawn in R**, watermarked "illustrative -- not a photograph". |
| `R/sysdata.rda` | The **CIE 1931 2° standard observer** colour-matching functions and **CIE standard illuminant D65**, 380-780 nm at 5 nm, used to turn a spectrum into a colour. A physical standard published by the CIE, which asks that it be cited: CIE 2019, *Colour-matching functions of CIE 1931 standard colorimetric observer*, International Commission on Illumination (CIE), Vienna, AT, DOI: [10.25039/CIE.DS.xvudnb9b](https://doi.org/10.25039/CIE.DS.xvudnb9b); CIE 2019, *CIE standard illuminant D65*, International Commission on Illumination (CIE), Vienna, AT, DOI: [10.25039/CIE.DS.hjfjmt59](https://doi.org/10.25039/CIE.DS.hjfjmt59). |

## What it reads at run time, and never ships

| Data | Source and licence | How soilKey obtains it |
|---|---|---|
| Parsed WRB 2022 and *Keys to Soil Taxonomy* 13th-edition criteria (`WRB_4th_2022`, `ST_criteria_13th`, `ST_features`) | the [`SoilTaxonomy`](https://github.com/ncss-tech/SoilTaxonomy) R package, NCSS-tech, **GPL-3** | read from the installed package (a Suggests) by `canonical_reference()` |
| KST 13th-edition codes and criteria (`2022_KST_codes.json`, `2022_KST_criteria_EN.json`) | [`SoilKnowledgeBase`](https://github.com/ncss-tech/SoilKnowledgeBase), NCSS-tech, **GPL-3** | downloaded on first use by `kst13_codes()` and `coverage_report()`, pinned to commit `9e78a75`, checked by MD5, cached in `tools::R_user_dir("soilKey", "cache")` |
| WoSIS soil profiles | ISRIC — World Soil Information, licensed **per profile** by each provider (CC BY, CC BY-NC or public domain) | queried live by `read_wosis_profiles_graphql()`, which by default lists only profiles free of a NonCommercial restriction and carries each profile's licence and dataset into the pedon |

## Where the benchmark data comes from, and how to get it

The benchmarks in this package read databases that soilKey does not ship. To
run them, obtain the data yourself from the provider, under the provider's
terms:

| Source | Provider | How soilKey reads it |
|---|---|---|
| WoSIS | ISRIC — World Soil Information | `read_wosis_profiles_graphql()`, then `benchmark_run_classification()` |
| KSSL / NASIS | USDA-NRCS National Soil Survey Center | `load_kssl_pedons_gpkg()`, `load_kssl_pedons_with_nasis()` |
| Africa Soil Profiles | AfSP / ISRIC | `load_afsp_pedons()`, `benchmark_afsp()` |
| LUCAS Soil 2018 | European Soil Data Centre (ESDAC), JRC | `benchmark_lucas_2018()` |
| Redape | Embrapa; Vaz, Silva Jr & Silva Neto (2023), DOI [10.48432/PYKKA7](https://doi.org/10.48432/PYKKA7) | `benchmark_redape()` |
| BDsolos | Embrapa | `download_bdsolos()`, `benchmark_bdsolos()` |
| FEBR | UFSM | `read_febr_pedons()` |
| OSSL | Soil Spectroscopy for Global Good | `download_ossl_subset()` |
| SoilGrids | ISRIC | fetched live at the user's coordinates |

Each of those functions performs the request **from the user's own machine,
under the user's own relationship with the provider**. soilKey never holds a
copy.

The benchmark *scripts* live in `inst/benchmarks/`. The reports they produce
are results computed from those databases, so they are written locally when a
script runs and are not part of the package or its repository.

## History

* **Up to v0.9.198** the package bundled a 40-profile WoSIS snapshot
  (`inst/extdata/wosis_sa_sample.rds`, pulled from
  `https://graphql.isric.org/wosis/graphql` on 2026-05-03). All 40 profiles
  belong to the AR-SOTER dataset under CC BY 3.0, which permits redistribution
  with attribution; the snapshot had dropped the licence and dataset fields that
  attribution needs. Four larger benchmark caches (AfSP, KSSL, KSSL+NASIS, WoSIS
  stratified) were kept in the development repository. **v0.9.199** removed all
  five.
* **Up to v0.9.203** soilKey vendored three datasets from `SoilTaxonomy` and two
  JSON files from `SoilKnowledgeBase`, both GPL-3, inside the MIT-licensed
  package. **v0.9.204** stopped: the first are read from the installed package,
  the second downloaded on first use. Both were checked byte-identical to their
  sources before removal, so no result changed. v0.9.204 also removed the
  benchmark reports and replaced the demonstration spectrum, whose origin was
  not on record, with a documented synthetic one.
* The published **CRAN tarball for v0.9.184** contains the WoSIS snapshot, the
  five vendored GPL-3 reference files, and 90 benchmark reports. The reports
  hold aggregate accuracy tables; a search for per-profile identifiers and
  coordinates found none. Anyone reviewing that release should read it in that
  light.
* The development history, which contains the removed files, is kept private.
  The public repository begins from a single commit of the cleaned tree.
